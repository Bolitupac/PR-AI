## Chapter 3: Importing Code & Repositories {#chapter-3-importing}

PR-AI supports multiple import methods. Here's how to use each:

### Method 1: Import from Repository Provider

**Step-by-Step:**

1. Click the **"Import"** button (top right of Auditor)
2. Select **"Import from repo provider"**
3. **Choose a provider** (GitHub, GitLab, Bitbucket, Azure)
4. You'll be redirected to the **Imports page**

**GitHub & GitLab sign-in:** Use **Sign in with GitHub** or **Sign in with GitLab** on the login page. No manual token is required for gitlab.com or github.com. Self-hosted GitLab can use **Settings → GitLab** with a Personal Access Token and custom base URL.

**On the Imports Page:**

- **Recent Pull Requests** panel (left) shows your latest PRs
- **Recent Commits** panel (left) shows recent commits
- **Main panel** displays all your repositories

**Selecting a Repository:**

1. Click on a repository in the main panel
2. The UI expands to show:
   - **Branches** - Compare branch with main
   - **Pull Requests** - Select an open PR to audit
   - **Commits** - Pick recent commits for analysis

**Branch Audits Explained:**

⚠️ **Important:** Branch audits compare the **selected branch with the main branch**. This gives you a high-level view of all changes introduced on that branch.

**Branch audits** compare a selected branch to a base branch. **Pull request / merge request** and **commit** audits load remote diffs from GitHub or GitLab into the Auditor.

**Selecting a Pull Request:**

1. Choose a PR from the list
2. The audit loads in the main Auditor workspace
3. The diff viewer automatically shows at the bottom
4. The AI begins analyzing the changes
5. Start chatting with the AI about the review

**Selecting a Commit:**

1. Click on a commit from the Recent Commits list
2. The commit diff loads in the auditor
3. The git diff visualization shows what changed
4. Ask the AI specific questions about the commit

### Method 2: Upload a Diff File

**Step-by-Step:**

1. Click the **"Import"** button or the **"Plus" button** (+) in the chat area
2. Select **"Upload diff file"**
3. Choose a `.diff` or `.patch` file from your computer
4. The file uploads and the diff appears at the bottom
5. The AI begins analysis

**Supported Formats:**
- `.diff` files (unified diff format)
- `.patch` files (Git patch format)
- Raw diff output from `git diff` command

**Important Note:** Ensure your diff file is in standard unified diff format, or it may not render correctly in the diff viewer.

### Method 3: Paste Diff or Code Manually

**Step-by-Step:**

1. Click the **"Plus" button** (+) in the chat area
2. Select **"Paste diff/code"**
3. A **Monaco Editor** opens (VS Code–like code editor)
4. Paste your diff or code into the editor
5. Click **"Audit"** or **"Analyze"** button
6. The content loads and the diff viewer displays it

**What to Paste:**

You can paste:
- Git diffs (from `git diff output`)
- Pull request diffs (from GitHub/GitLab API)
- Raw code changes
- Any text-based code snippet

**⚠️ Critical:** For Git diff to render at the bottom, the pasted content must be in **valid diff format**. If you paste raw code without diff markers, the diff viewer won't show it—but you can still chat with the AI about the code.

**Valid Diff Format Example:**
```
--- a/src/index.js
+++ b/src/index.js
@@ -10,3 +10,5 @@
 function greet() {
   console.log("Hello");
+  console.log("Updated");
+  console.log("New line");
 }
```

**Invalid (raw code, no diff markers):**
```
function greet() {
  console.log("Hello");
  console.log("Updated");
}
```

### Why Git Diff Matters

The **Git Diff Viewer at the bottom** is crucial for effective code review because it:

✅ Shows added lines in **green**  
✅ Shows removed lines in **red**  
✅ Displays context lines in **gray**  
✅ Highlights syntax with color coding  
✅ Makes it easy to spot changes at a glance  

**If your diff doesn't appear:**
1. Verify it's in valid **unified diff format**
2. Check that it contains `---` and `+++` lines with file paths
3. Try re-uploading or re-pasting the diff

## Chapter 4: AI Auditing Modes {#chapter-4-auditing-modes}

### Overview

PR-AI supports **four types of audits**, each designed for different review scenarios:

| Audit Type | What It Does | Best For |
|---|---|---|
| **Pull Request Audit** | Analyzes a complete PR with all changes and comments | Full code review before merging |
| **Commit Audit** | Focuses on changes in a single commit | Reviewing specific work, understanding commit history |
| **Branch Audit** | Compares an entire branch against main | High-level branch review (currently main only) |
| **Manual/Paste Audit** | Audits code or diffs you paste manually | Quick reviews, snippets, external code samples |

### How Audits Work

**The AI Automatically:**

1. ✅ Reads all changed lines in the code
2. ✅ Analyzes the diff context (lines before/after changes)
3. ✅ Reviews pull request metadata (title, description)
4. ✅ Extracts and incorporates any PR comments or discussions
5. ✅ Runs automated checks for:
   - Security vulnerabilities
   - Performance issues
   - Code style violations
   - Logic errors
   - Dependency risks
   - Best practice violations

**The AI Returns:**

- A structured **summary** of findings
- **Risk signals** (high/medium/low severity)
- Specific line-by-line insights
- Architecture impact analysis
- Recommendations for improvement
- **Mermaid diagrams** (if relevant)

### Understanding Audit Limitations

⚠️ **Important:** PR-AI is in **early stage development**. You should expect:

- Occasional inaccurate suggestions
- Sometimes missing obvious issues
- AI models making reasoning mistakes
- False positives or negatives
- Improved accuracy as the tool evolves

**Always use PR-AI as an assistant**, not a replacement for human review. Critical code should still be reviewed by team members.

## Chapter 7: Git Diffs Visualization {#chapter-7-diffs}

### Understanding the Diff Viewer

The **Git Diff Viewer** appears at the bottom of the Auditor workspace and shows:

✅ **Side-by-side or unified view** of code changes  
✅ **Added lines** (typically green)  
✅ **Removed lines** (typically red)  
✅ **Context lines** (unchanged, gray background)  
✅ **Syntax highlighting** for better readability  
✅ **File headers** showing file names and paths  
✅ **Line numbers** for reference  

### When Does the Diff Viewer Appear?

The diff viewer only appears after you've:

1. **Imported a repository** (GitHub PR, commit, or branch)
2. **Uploaded a diff file** (.diff or .patch)
3. **Pasted valid diff-formatted code** (with `---` and `+++` markers)

**If you paste raw code without diff formatting**, the AI can still analyze it, but the diff viewer won't render.

### Reading the Diff Viewer

**Example diff:**
```
--- a/src/auth.js
+++ b/src/auth.js
@@ -15,6 +15,8 @@ function authenticate() {
   const token = getToken();
+  // Added validation
+  if (!token) return null;
   return validateToken(token);
 }
```

**Color Coding:**
- 🟢 **Green lines with +** = New code added
- 🔴 **Red lines with -** = Code removed
- ⚪ **White/gray lines** = Context (unchanged code)
- 🔵 **Blue headers** = File information

**Header Example:**
```
--- a/src/index.js      ← Old file path
+++ b/src/index.js      ← New file path
@@ -10,5 +10,7 @@    ← Hunk header (line numbers)
```

### Interacting with the Diff

**Click on a line** to:
- Highlight it
- Reference it in your chat with the AI
- Ask specific questions about that change

**Scroll through the diff** to:
- Review all changes in a file
- See multiple files if PR contains many changes
- Understand the full scope of changes

### Diff Viewer Keyboard Shortcuts

| Shortcut | Action |
|---|---|
| `↑` / `↓` | Scroll through diff |
| `Ctrl+F` | Search within diff |
| `+` / `-` | Zoom in/out (browser) |

### What If Diff Doesn't Appear?

**Issue:** You uploaded a file or pasted code, but the diff viewer at the bottom is empty.

**Solutions:**

1. **Verify diff format** - Is your content in valid unified diff format?
   - Valid: Content starts with `---` file path line
   - Invalid: Raw code without diff markers
2. **Check file type** - Ensure uploaded file is `.diff`, `.patch`, or text
3. **Re-upload/paste** - Try uploading or pasting the content again
4. **Still can't see it?** - The AI can still analyze raw code; just ask questions in chat

## Chapter 9: API Key Management {#chapter-9-api-keys}

### Two-Mode Key System

PR-AI supports **two ways** to handle OpenAI API keys:

#### **Mode 1: Developer Key (Shared/Free)**

- Uses a **shared developer API key** provided by PR-AI
- No cost to you (PR-AI covers API costs for free tier)
- Limited usage quotas
- Good for: Getting started, light usage, teams

**How to Use:**
1. Sign up for PR-AI
2. You're automatically in "Developer" mode
3. Start auditing immediately
4. No API key needed

#### **Mode 2: Personal Key (Your Own)**

- You provide **your own OpenAI API key**
- You control billing and costs
- Full quota limits (your OpenAI account limits)
- Good for: Heavy usage, enterprises, cost control, privacy

**How to Set Up:**

1. Get your OpenAI API key:
   - Go to [platform.openai.com/api-keys](https://platform.openai.com/api-keys)
   - Create a new API key
   - Copy the key (you'll only see it once)

2. Add it to PR-AI:
   - Click **Settings** in sidebar
   - Go to **"API Keys"** section (or **"Apps"** → **"AI Keys"**)
   - Paste your OpenAI key
   - Click **"Save"**

3. Switch to Personal mode:
   - Once saved, click the toggle to switch to **"Personal"** mode
   - All subsequent audits use your key
   - You're billed directly through OpenAI

### Switching Between Modes

**In Settings:**

1. Click **Settings** (gear icon) in sidebar
2. Find **"API Key Mode"** section
3. Toggle between:
   - **Developer** - Uses shared key
   - **Personal** - Uses your key

**Visual Indicator:**

- Shows your current mode
- Shows masked version of personal key (if saved)
- Shows remaining quota if using developer key

### Managing Your Personal Key

**View your masked key:**
- Settings shows `sk-••••••••••••••••1234` (last 4 characters visible)

**Remove your key:**
- In Settings, click **"Remove"** next to your key
- You'll return to Developer mode

**Change your key:**
- Remove the old key
- Add a new key
- Verify it works with a test audit

### Billing Considerations

**Developer Mode (Free Tier):**
- ✅ $0 out of pocket
- ❌ Limited audits per month
- ❌ Slower response times during peak usage
- ❌ May have queue delays

**Personal Mode (Your Key):**
- 💰 Pay per API call to OpenAI
- ✅ Unlimited audits (within your account limits)
- ✅ Priority access (your key = your priority)
- ✅ Better performance

**Estimated Costs** (using Personal Key):

| Audit Type | Estimated Cost |
|---|---|
| Small PR (< 50 lines) | $0.01 - $0.05 |
| Medium PR (50-500 lines) | $0.05 - $0.20 |
| Large PR (500+ lines) | $0.20 - $1.00 |
| DocGen output | $0.10 - $0.50 |

*Costs depend on model choice, token usage, and current OpenAI pricing*

### Known Issues & Bugs ⚠️

PR-AI is in **early stage development**. Expect these known issues:

#### **False Positives**
- AI may flag safe code as risky
- Sometimes suggests unnecessary changes
- Not always 100% accurate in analysis

**Workaround:** Cross-check AI suggestions with your domain knowledge

#### **Incomplete Diffs**
- Large files (>10MB) may not render fully in diff viewer
- Some binary files are skipped
- Some special characters may not display

**Workaround:** Review large files in chunks; upload split diffs

#### **Voice Transcription Errors**
- Accents may cause transcription mistakes
- Background noise affects accuracy
- Short words sometimes misheard

**Workaround:** Speak clearly; use typed prompts for critical reviews

#### **Diagram Generation**
- Complex code may not generate useful diagrams
- Some logic flows may be oversimplified
- Mermaid rendering has browser compatibility issues

**Workaround:** Request specific diagram types; use typed descriptions

#### **Performance on Large PRs**
- PRs over 5000 lines may take longer to analyze
- API timeouts on extremely complex changes
- Response times slower during peak hours

**Workaround:** Split large PRs; use during off-peak hours; request personal key for priority

#### **Session Timeouts**
- Long inactive periods may disconnect
- Voice recording may stop unexpectedly
- Chat history may not persist on browser clear

**Workaround:** Save important audits; restart if issues occur; clear cache periodically

3. **Provide the code** (if possible) that triggered the issue
